# JIDU6101: install OpenWrt

The JIDU6101 is an Arcadyan-built MediaTek `6j01` router. OpenWrt supports it
officially from 25.12.6. This page is the flashing guide for that model: SSH
first, the official image as the result, and the UART route as the fallback.
The shared reasoning is in [Installing OpenWrt by
hand](../../OPENWRT.md#mediatek-6j01-jidu-6101--6201--6401--6601--6701).

> [!TIP]
> **Primary route: SSH.** It writes the shared `jidu6j01` stage 1,
> then the official `jidu6101` sysupgrade. The stage 1 reports
> `jidu6j01`, so the 6101 image needs `-F`; route B avoids the force.

> [!WARNING]
> Flashing replaces the stock firmware permanently. Back up first. The official
> image needs 25.12.6 or newer: older 25.12 builds could silently fail to write
> the SPI-NAND. The community stage 1 in route A performs that write; if it
> predates the fix, use route B.

## Pick a route

| Route | Stage 1 | Stage 2 | Needs |
| --- | --- | --- | --- |
| **A, SSH (primary)** | community `jidu6j01` factory.ubi | official `jidu6101` sysupgrade (`-F`) | root SSH |
| **B, UART + TFTP (official)** | official `jidu6101` initramfs | official `jidu6101` sysupgrade | UART + TFTP |

Both routes end on the official image. Route A is faster. Route B skips the
community stage 1, so it is the safer choice if the community build predates
the SPI-NAND fix.

## What is different on the JIDU6101

Official support for the 6101 is separate from the other four: its files use
`jidu6101`, and its device tree is `mt7986a-jiorouter-ax6000-jidu6101`.

Its MAC address comes from the `u-boot-env` partition (`mac` as text), not from
MFG like the `jidu6j01` variants.

The DIY repo's `6101_commands.md` documents the official UART install. Its
latest-firmware notes also list the 6101 under the 6j01 SSH method, which
writes the shared `jidu6j01` stage 1. This page then installs the official
`jidu6101` sysupgrade with `-F`; route B installs it without forcing.

No UART pin photo is hosted here. Route A avoids UART; route B
needs you to find the header first.

## Before you start

- [ ] `./flash.sh backup` has finished. The folder has `uboot_credentials.env`
  and one `.bin` per partition.
- [ ] Root SSH works: `ssh -i ~/.ssh/idu_rsa root@192.168.31.1`.
- [ ] The community `jidu6j01` factory image and the official `jidu6101`
  sysupgrade are in one folder. Rename it to `sysupgrade.bin`.
- [ ] For the UART fallback: a UART adapter at 3.3 V, a TFTP server, and the
  official initramfs and sysupgrade from 25.12.6 or newer.
- [ ] An Ethernet cable. Do not flash over Wi-Fi.

## Route A: SSH (primary)

This is the route this project uses. It writes a community `factory.ubi` to the
spare slot, boots it, then installs the official sysupgrade. The community
stage 1 is only the vehicle; both routes end on the official image. The stage 1
reports `jidu6j01`, so the official `jidu6101` image needs `-F`. If you do not
want to force it, use route B.

### A1. Confirm the layout

On the router:

```sh
ssh -i ~/.ssh/idu_rsa root@192.168.31.1
cat /proc/mtd
```

Expect `mtd6` to be `ubi2`, the vendor's spare slot. If it does not match,
stop and compare it with `partitions.txt` in your backup.

### A2. Send the community stage 1

From your PC, in the folder with the community images:

```sh
scp -O openwrt-mediatek-filogic-jiorouter_ax6000-jidu6j01-initramfs-factory.ubi \
    root@192.168.31.1:/tmp/
```

### A3. Write it and set the boot variables

On the router:

```sh
ubidetach -m 6
ubiformat /dev/mtd6 -y -f /tmp/openwrt-mediatek-filogic-jiorouter_ax6000-jidu6j01-initramfs-factory.ubi

fw_setenv bootcmd 'ubi detach; ubi part ubi2; ubi read 46000000 kernel; fdt addr $(fdtcontroladdr); fdt rm /signature; bootm 0x46000000'
fw_setenv dual_boot.current_slot 1
fw_setenv dual_boot.slot_0_invalid 1
fw_setenv dual_boot.slot_1_invalid 1
fw_setenv ipaddr
```

**Point of no return** for the stock system on `mtd6`. Keep the single quotes:
`$(fdtcontroladdr)` must reach U-Boot literally.

### A4. Boot the temporary system

```sh
reboot
```

Wait about a minute, then:

```sh
ssh root@192.168.1.1
```

### A5. Install the official sysupgrade

From your PC, in the folder with `sysupgrade.bin`:

```sh
scp -O sysupgrade.bin root@192.168.1.1:/tmp/
ssh root@192.168.1.1 "sysupgrade -F /tmp/sysupgrade.bin"
```

`-F` is required because the stage 1 reports `jidu6j01` but this image is
`jidu6101`. It is the correct 6101 build, but forcing it skips the board-name
check. Have the backup and a UART recovery path ready, or use route B.

It reboots into the official image. Wait for `192.168.1.1`, then set a root
password.

## Route B: UART + TFTP (official fallback)

This is the unforced official install. The DIY repo has a dedicated
`6101_commands.md` with the same steps.

### B1. Download and rename the files

Get the pair from the [firmware selector](https://firmware-selector.openwrt.org/).
For this model they are:

```text
openwrt-<version>-mediatek-filogic-jiorouter_ax6000-jidu6101-initramfs-kernel.bin
openwrt-<version>-mediatek-filogic-jiorouter_ax6000-jidu6101-squashfs-sysupgrade.bin
```

Rename them so the commands below stay short:

```sh
mv openwrt-*-jidu6101-initramfs-kernel.bin initramfs.bin
mv openwrt-*-jidu6101-squashfs-sysupgrade.bin sysupgrade.bin
```

### B2. Prepare the TFTP server and UART

Put `initramfs.bin` in the root of a TFTP server and give your PC the address
`192.168.1.2` on the Ethernet interface you will use. Connect the UART adapter
at **115200 8N1** and open the console.

### B3. Stop the boot

Power on the router. At the boot menu, select **Failsafe Mode**, then press
`Ctrl-C` to interrupt and reach the U-Boot prompt.
The 6101 normally reaches it without a login. If it asks for a username and
password, they are in `uboot_credentials.env` from your backup.

### B4. Boot the initramfs

At the U-Boot prompt:

```text
setenv ipaddr 192.168.1.1
setenv serverip 192.168.1.2
tftpboot 0x46000000 initramfs.bin
fdt addr $(fdtcontroladdr)
fdt rm /signature
bootm
```

`$(fdtcontroladdr)` is typed literally. `fdt rm /signature` removes the vendor
signature node, which is what lets the unsigned OpenWrt image boot.

Nothing is written to the flash in this step. If it fails, power-cycle and the
stock system is still there.

### B5. Install the sysupgrade

After about a minute the initramfs answers at `192.168.1.1`. From your PC, in
the folder with `sysupgrade.bin`:

```sh
scp -O sysupgrade.bin root@192.168.1.1:/tmp/
ssh root@192.168.1.1 "sysupgrade /tmp/sysupgrade.bin"
```

`unknown option -- O` means your `scp` is old; drop `-O` and retry. If SSH is
refused, open `http://192.168.1.1` and use **System → Backup / Flash Firmware →
Flash image…** with `sysupgrade.bin`. Do not tick *Keep settings*.

It writes the official image and reboots. Wait until it answers at
`192.168.1.1`, then set a root password.

## If it goes wrong

- **SSH is refused:** check that you are on `192.168.31.1` (stock) or
  `192.168.1.1` (temporary), and that Dropbear is running. If you skipped the
  unlock step, run `./flash.sh unlock` first.
- **`fw_setenv` is missing:** stock firmware should have it. If it does not,
  use route B.
- **It still boots stock:** check that `fw_setenv bootcmd` took, and that the
  three `dual_boot.*` variables are set. If it still boots stock, use route B.
- **Sysupgrade refuses the image:** the stage 1 reports `jidu6j01`, so the
  official `jidu6101` image needs `-F`. Only force it with the backup and a
  UART recovery path, or use route B.
- **TFTP times out:** check the PC address (`192.168.1.2`), the TFTP root, the
  firewall, and that the file is named exactly `initramfs.bin`.
- **`Bad FIT` or a signature error:** `fdt rm /signature` was missed, or
  `$(fdtcontroladdr)` was expanded by your shell. Type it literally.
- **No UART output:** check 3.3 V, TX/RX crossing, and 115200 8N1.
- **Sysupgrade fails:** do not power off halfway. If the flash was not touched,
  power-cycle back to stock. If it was, restore from the backup over UART.
- **UART pins:** No pin photo is hosted here. Route A avoids
  UART; for route B, identify the header before you connect anything.
- **Revert:** the backup has every partition. The
  [family FAQ](../../OPENWRT.md#faq) has the 6j01 restore steps, and the model
  pages have the per-model notes.
