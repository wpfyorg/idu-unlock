# JIDU6111: install OpenWrt

The JIDU6111 is a Qualcomm `6j11` router. This page is the
flashing guide for that model: the files to use, the commands that apply, and
what is different from its siblings. The reasoning behind every step is in
[Installing OpenWrt by hand](../../OPENWRT.md#qualcomm-6j11-jidu-6111--6411--6611--6811--6911).

OpenWrt does not publish an official image for the 6j11. The community build is
the only OpenWrt image for this family.

> [!TIP]
> **Primary route: SSH (Mayank method).** UART is recovery only.

> [!WARNING]
> Flashing replaces the stock firmware permanently. Back up first, and read the
> family guide once before you type anything.

## Pick a route

| Route | Needs | Use it |
| --- | --- | --- |
| **A, SSH (Mayank method, primary)** | root SSH and the community files | the normal path |
| **B, UART (recovery)** | 3.3 V adapter and the U-Boot console | recovery only |

## What is different on the JIDU6111

All five 6j11 models use the same Mayank SSH method and the same community
factory image. There is no per-model build to pick.

Never copy the `mtdN` numbers from another unit. The active slot and its
geometry depend on that unit's OTA history; read `/proc/cmdline` and
`/proc/mtd` on your own router first.

No UART pin photo is hosted here. Confirm the pinout independently before connecting.

## Before you start

- [ ] `./flash.sh backup` has finished, with one `.bin` per partition.
- [ ] Root SSH works: `ssh -i ~/.ssh/idu_rsa root@192.168.31.1`.
- [ ] Both image files are in one folder on your PC.
- [ ] An Ethernet cable is connected. Do not flash over Wi-Fi.
- [ ] A UART adapter at 3.3 V for recovery, or just your existing SSH session
  for route A.

## Route A: SSH (Mayank method, primary)

These are the `6j11` commands with nothing left to fill in, except where
your own router's numbers are the answer. `scp` runs from your PC, in the image
folder. The rest runs on the router.

### A1. Find the idle slot

```sh
ssh -i ~/.ssh/idu_rsa root@192.168.31.1
cat /proc/cmdline
cat /proc/mtd
```

`/proc/cmdline` names the active slot, either `ubi.mtd=rootfs` or
`ubi.mtd=rootfs_1`. The other one is idle, and that is the slot OpenWrt goes
into. Stock on the active slot stays untouched until step 6.

### A2. Send the factory image

```sh
scp -O openwrt-qualcommbe-ipq95xx-jiorouter_ax6000-jidu6j11-initramfs-factory.ubi root@192.168.31.1:/tmp/
```

Use the community build for this route. The upstream UART builds ship
`...-initramfs-uImage.itb` instead, which is not what goes on the flash here.

### A3. Read the idle slot's geometry

```sh
IDLE=rootfs_1                       # the one NOT in /proc/cmdline
grep "\"$IDLE\"" /proc/mtd           # mtd23: 05000000 00020000 "rootfs_1"
cat /sys/class/mtd/mtd23/offset     # 0x1700000
cat /sys/class/mtd/mtd23/size       # 0x5000000
```

Every unit can differ. Use the numbers your own router prints, not the ones in
this example.

### A4. Write it and point the bootloader at it

```sh
ubidetach -m 23
ubiformat /dev/mtd23 -y -f /tmp/openwrt-qualcommbe-ipq95xx-jiorouter_ax6000-jidu6j11-initramfs-factory.ubi

fw_setenv mtdids 'nand0=nand0'
fw_setenv mtdparts 'mtdparts=nand0:0x5000000@0x1700000(rootfs_1)'
fw_setenv bootcmd 'ubi detach; ubi part rootfs_1; ubi read 0x46000000 kernel; bootm 0x46000000'
reboot
```

The offset and size in `mtdparts` are the ones from step 3. Keep the single
quotes: the `( )` have to reach u-boot as they are.

### A5. Boot the temporary system

Wait 90 seconds, then:

```sh
ping 192.168.1.1
ssh root@192.168.1.1
```

### A6. Install the permanent system

```sh
scp -O openwrt-qualcommbe-ipq95xx-jiorouter_ax6000-jidu6j11-squashfs-sysupgrade.bin root@192.168.1.1:/tmp/

ssh root@192.168.1.1 "sysupgrade -v -n /tmp/openwrt-qualcommbe-ipq95xx-jiorouter_ax6000-jidu6j11-squashfs-sysupgrade.bin"
```

`-n` means do not keep settings. The connection drops mid-command; that is
normal. Wait another 90 seconds. Both slots become one ~225 MB `ubi`, and the
stock firmware is gone at that point.

## After it boots

Set a root password at `http://192.168.1.1` under **System → Administration**,
or over SSH:

```sh
passwd
```

The stock address `192.168.31.1` is gone. From here the router is a normal
OpenWrt box at `192.168.1.1`.

## Route B: UART recovery

Open the case only if the SSH route will not boot. The family guide has the
full UART steps and the `bootcmd` and `bootargs` lines:
[UART recovery](../../OPENWRT.md#route-b-uart-recovery-u-boot-over-serial).

## If it goes wrong

- **`No Kernel Found` on the first boot:** set `mtdids` and `mtdparts` at the
  u-boot prompt with your unit's geometry, then boot again. The exact lines are
  in the [family FAQ](../../OPENWRT.md#faq).
- **Back to stock:** put your saved `mtd23` and `mtd24` images back with
  `mtd -e`, then `setenv bootcmd 'bootipq'` in the u-boot console. The steps
  and the `bootargs` line are in the [family FAQ](../../OPENWRT.md#faq).
- **UART login:** the credentials are in `uboot_credentials.env` in your
  backup. No UART pin photo is hosted here; confirm the pinout independently before connecting.

The [family FAQ](../../OPENWRT.md#faq) covers the rest.
